# doc-gate-kit —— 文档层闸门（可复用套件）

一个**跨项目共用**的文档检查套件：判据只维护一份，新项目只放一个基线和 5 行 workflow。

只判两条**与业务无关**的规则：

| 判据 | 判什么 | 为什么值得占一个 CI 位 |
|---|---|---|
| **死链** | Markdown 里 `[文字](相对路径)` 的目标在不在 | 路径写错、文件被挪、链接指到不入库的生成物——这三类靠人眼查不出来 |
| **编码** | 非法 UTF-8／`U+FFFD`／异常控制字符 | 中文被静默截断的文件能通过 `git`、`cat`、`file`，肉眼也看不出，打开才炸，且**不可逆** |

**刻意不判**：编号体例、模板节数、目录表规矩、接口与字段是否对齐。那些是**各项目自己的口径**，抄过来只会制造假红——假红会训练人无视红灯。

---

## 一、为什么是"套件 + 薄调用"，而不是每个项目拷一份

**判据只能有一份。** 如果新项目里也放脚本，就会出现本机跑旧判据、CI 跑新判据，结果是
"本地绿、CI 红"——**那比不装更坏，因为你会开始不信红灯**。

所以本套件的分工是：

| 放什么 | 放哪 | 每项目各一份？ |
|---|---|---|
| 3 个检查脚本 | **只在本仓库** | ❌ |
| `扫描目录` ＋ 基线读数 | 各项目的 `03_项目工具/闸门基线.json` | ✅ |
| 5 行 workflow | 各项目 `.github/workflows/docs.yml` | ✅ |
| 薄 pre-commit 钩子 | 各项目 `.git/hooks/pre-commit`（调本仓库） | ✅（不入 git，需重装） |

升级判据 = 改本仓库一次，所有项目下次 push 自动跟上。

## 二、装进新项目：一条命令

```sh
cd ~/work/新项目          # 必须在 git 仓库根
sh ~/tools/doc-gate-kit/install.sh            # 自动探测 docs/ 文档/ 方案/
sh ~/tools/doc-gate-kit/install.sh docs 方案   # 或显式指定要扫的目录
```

它会做七件事，**一件都不覆盖你已有的文件**：

1. 写 `03_项目工具/闸门基线.json`（只登记扫描目录，读数留空）
2. 写 `.github/workflows/docs.yml`（自动从本仓库 remote 推断 `owner/repo`）
3. 装薄 `pre-commit` 钩子（已有 `core.hooksPath` 或已有钩子时**只警告、不覆盖**）
4. **跑尺子自检**：塞坏链接看它红不红——不红就报失败
5. 空跑一次，把现有问题逐条列出来
6. **不落基线**，把定性权留给人

### 装完必须做：落基线（这一步不能省）

第一次空跑一定会报出历史旧账。**不要 `--update-baseline` 一把拍平**——那等于把旧账埋了。
正确顺序：

1. 看明细，逐条定性：**真该修**就修；确实是"本机才有、不入库的素材"
   （且路径已被 `.gitignore` 覆盖）本来就不会计入；
2. 定性完再落基线，并把每条 `登记` 改成"谁、什么时候、接受了什么"：

```sh
node ~/tools/doc-gate-kit/run_docs_gate.mjs --root "$(pwd)" --update-baseline
```

## 三、退出码三档（调用方要区别对待）

| 码 | 含义 | CI 里 | pre-commit 里 |
|---|---|---|---|
| **0** | 不比基线差 | 绿 | 放行 |
| **1** | 比基线差（真的新增了缺陷） | **红** | **拦住** |
| **2** | **闸门自己跑不成**（配置缺／目录空／脚本异常） | **红**（"闸门坏了"必须有人管） | **放行**（fail-open，守卫坏了不能挡住干活） |

`2` 在两边处理不同，是刻意的：**"没查成"既不等于"通过"，也不该拦人干活**。
钩子里遇到 2 会放行，但 CI 里 2 必须是红——否则闸门某天静默失效，没人知道。

## 四、怎么验这套东西真的有用（只验绿等于没验）

| 做坏什么 | 期望 |
|---|---|
| 写一个指向不存在文件的链接 | 退出 1，明细点名那一行 |
| 往文本文件塞非法 UTF-8 字节 | 退出 1，报"不是合法 UTF-8" |
| 撤掉上面两处 | 退出 0 |
| 把 `扫描目录` 改成空数组 | 退出 **2**（"没东西可查"不许绿） |
| 删掉基线文件 | 退出 **2** |
| 让链接指向 `.gitignore` 忽略的文件、再删掉那个文件（模拟干净检出） | 仍退出 **0** |

随时可跑内置自检（不动项目文件）：

```sh
node ~/tools/doc-gate-kit/run_docs_gate.mjs --self-test
```

它会自己造干净样本、造坏链接、造非法 UTF-8，确认三样都判对。

## 五、最容易被忽略的一个坑（本套件已修）

`git check-ignore` 输出**中文／非 ASCII 路径**时默认会 **C 转义并加双引号**
（`"04_\347\224\237..."`）。如果直接拿它的 stdout 建集合，会与原始中文路径
**永远匹配不上**，那条"被 `.gitignore` 忽略就不算死链"的豁免会**静默失效**：

- **本机看不出来**（被忽略的文件都在盘上，只有"目标缺失"那一支才走这个判断）；
- **一进 CI 就炸**（干净检出里它们必然缺，于是几十处环境必然被报成硬缺陷）。

修法是一行：`git -c core.quotePath=false check-ignore ...`。
**`-z` 不能替代**——它只配 `--stdin` 才有意义（试过，git 直接报 `fatal`）。

这件事本身就是这套东西存在的理由：**闸门装了、报表是绿的，不等于它真的在判。**

## 六、三层"自动"的真实边界（实测，不要相信"全自动"）

| 要内置的东西 | 能真自动吗 | 机制 | 硬限制 |
|---|---|---|---|
| 提交时检查 | ✅ 装一次管所有仓库 | 全局 `core.hooksPath` | **只在这台机器**；且有项目级配置时**全局不生效** |
| push 时检查 | ⚠️ 半自动 | reusable workflow（本项目 4 行） | 仍要有人写那 4 行 |
| 脚本文件本身 | ❌ 不能 | 必须在某个仓库里 | CI 只认仓库里的文件 |

实测两条结论：

- `git init --template` 只会把文件拷到 `.git/` 里，**不进工作区**，且 **`clone` 完全不用模板**；
- 项目里设了 `core.hooksPath` 时，全局钩子**不生效**（项目级优先）——所以"全局兜底"和"项目自带"不能同时成立。

**真正能跨机器保证的只有 CI。** 本机那一层一律是"尽力而为"，别把它当保证。

## 七、升级与维护

- 判据改了 → 只改本仓库，所有项目自动跟上（这也意味着**一次改错会影响所有项目**，
  所以本仓库自己也要有 CI，且每次改完先跑 `--self-test`）。
- 套件目录**移动到别处** → 各项目的薄钩子里写的是绝对路径，会失效。
  重跑 `install.sh` 会提示已有钩子、不覆盖；需要手工改钩子里的 `KIT=` 那一行。
- **不要把本套件的脚本拷进被检查的项目**——那就回到"两份判据"的老路了。

---

## 八、已知局限（照实写）

1. **判不了语义**：比如"代码读错了同名列"这种错，两边的列都在、文档也都写了，结构比对报不出来；
2. **只判 Markdown**：`.vue`／`.py` 里的路径错误不在射程内；
3. **不查锚点**：`[x](a.md#某章节)` 只看 `a.md` 在不在，不看 `#某章节` 是否存在；
4. **编码判据会误报二进制伪装成文本**：若把 `.svg`／`.json` 当文本写了二进制内容，会报非法 UTF-8——这是对的，但值得知道；
5. **不覆盖 `core.hooksPath` 已有配置**：装了钩子也不会生效，需要手工接入（安装时会警告）。
