# doc-gate：把文档闸门装进项目

判据只有两条——**死链**、**编码**——全部维护在套件里。项目里只放**基线**和**4 行 workflow**，不拷脚本。

套件根就是本 skill 往上两层（skill 以软链形式挂在 `~/.dsh/skills/doc-gate`），先解析出来再用：

```sh
KIT=$(cd -P ~/.dsh/skills/doc-gate/../.. && pwd)   # 例：.../一息千行/doc-gate-kit
DG="$KIT/bin/dg"
```

## 第一步：分新老（这一步决定能不能自动落基线）

| 情况 | 命令 | 基线怎么落 |
|---|---|---|
| **新项目**（目录空、或刚 `git init`） | `dg new <目录>` | **自动落 0**：没有旧账，0 就是真 0 |
| **老项目**（已有文档） | `dg adopt [目录]` | **不落**，必须人逐条定性后再落 |
| 只想查、不想改 | `dg check [目录]` | 不动任何文件 |

```sh
sh "$DG" new ~/work/新项目        # git init → README → 装闸门 → 验证 → 首次提交
sh "$DG" adopt .                  # 老项目：只装钩子与 CI，基线留给人
sh "$DG" check .                  # 只跑
sh "$DG" self-test                # 用临时仓库验上面三条路（不改真实项目）
```

`dg new` 会拒绝非空目录——**这是刻意的**：把老项目当新项目装，等于把历史旧账一次性拍平。

## 第二步（只对老项目）：落基线

1. 看 `dg adopt` 空跑出来的明细；
2. 逐条定性：**真该修**就修；指向本机素材、且路径已被 `.gitignore` 覆盖的，本来就不会计入；
3. 定性完才落基线，并把每条「登记」写成"谁、什么时候、接受了什么"：

```sh
node "$KIT/run_docs_gate.mjs" --root "$(pwd)" --update-baseline
```

**不许**用 `--update-baseline` 一把拍平：那等于把旧账埋了，以后"新增的红"和"本来就红"再也分不出来。

## 三条禁令

1. **不要把套件脚本拷进项目**——两份判据必然跑偏（本地旧、CI 新 → 本地绿、CI 红，比不装更坏）。
2. **不要对老项目自动落基线**（见上）。
3. **退出码 2 不是"通过"**：它表示闸门自己没跑成（目录不存在／一份 Markdown 都没读到／配置缺），CI 里必须当红处理。

## 怎么读结果

- 退出码：`0` 不比基线差／`1` 比基线差／`2` 闸门跑不成。
- 摘要与明细：`03_项目工具/生成物/文档闸门摘要.md`（已进 `.gitignore`）。
- 钩子看**暂存区**（`--staged`），CI 看**全量**；工作区干净不代表索引干净，这两者不能互换。
